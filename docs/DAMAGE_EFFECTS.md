# 伤害加成规则数据

生成物：`public/damage-effects.json`。生成器：`scripts/build_damage_effects.py`。
回归：`tests/damage-effects.test.mjs`。只改这组数据与说明，不修改计算内核或页面。

## 来源与重建

- 本机 `nightreign-data-20261109`：执行文件 `1.3.3.0`，regulation `10350000`。
  展开 XML 默认值后读取 AttachEffectParam、SpEffectParam、EquipParamAntique、
  AttachEffectTableParam、EquipParamGoods、Magic 及本作简体中文 FMG。
- 本机 Paramdex `NR/Meta/SpEffectParam.xml`：字段含义与类别叠加注释。
  参数解释不是游戏运行观察；`metadata.runtimeVerified=false`。
- 本机 `damage-actions-20261113` 的 `bullet-prefix-refs.jsonl` 和
  `bullet-prefix-summary.json`：独立专项核对的 Bullet 前128字节。
  本生成器再次逐字节比较原始 `Bullet.param`，校验行 ID、行偏移和效果字段。
  348字节行的后220字节不解读，也不由静态引用推断必定执行。
- `public/effect_encyclopedia.json`：仅在需要时交叉核对相同等级不叠加、不同等级叠加。
  保留 NightreignQuickRef 的来源与 GPL-3.0 标记，不从说明文字抽取倍率。
  输入文件的路径、版本和 SHA-256 均记录在 JSON `metadata`。

```powershell
python scripts/build_damage_effects.py
python scripts/build_damage_effects.py --check
node --test tests/damage-effects.test.mjs
```

可指定 `--source-root`、`--bullet-evidence-root`、`--output`。
生成器不联网、不读取存档、不写其他数据源。

## 接口与范围

本版收录 209 条伤害规则，其中遗物 129 条、局内词条 70 条、临时增益 10 条。
计算器列出 45 件官方遗物，包括黑夜王 10 件、永夜王 8 件、角色专属 25 件、特殊遗物 2 件。15 件至少含有一条已接入的伤害规则，另外 30 件可查看完整的自带词条。

`effects[].id` 是唯一字符串，例如 `relic:7001400:final:physical`；
`nativeEffectId` 是真实 AttachEffectParam ID，`spEffectId` 为实际倍率所在行。
同一来源若属性倍率不同会拆成多个规则，不能只取数组中第一条。
临时增益使用 `goodsId` 或 `magicId`，并用 `buffId` 将其全部规则绑定。

`relics[].id` 是真实 EquipParamAntique ID，`effectIds` 引用计算规则的字符串 ID。
生成器通过 `items_data.json` 的物品键匹配 `relic_catalog_zh.json` 的中文分类和本地图标，再对照游戏简中 AntiqueName 核实名称。每条效果通过该遗物槽位引用的 AttachEffectTableParam 单一候选确定。
`rows` 与 `nativeEffectIds` 按游戏槽位保留全部效果，`unmodelledEffectIds` 列出尚未接入的词条。
例如安定者的遗志（2070）和安定的遗志（2071）都有提升近战攻击力、提升战技攻击力。前者第三条是持续恢复专注值，后者第三条是减伤率降低时偶尔使敌人攻击失效。两项均在计算器内标为未计入。
存档里的随机遗物则由遗物仪式按实际实例带回对应词条。

### 计算阶段与属性

当前收录的倍率全部来自 `physics/magic/fire/thunder/darkAttackRate`，因此为
`phase: final`，在防御后作用于相应命中分量。原生 `dark` 对应圣属性 `holy`，
不是新增的第六属性。“提升攻击力”的中文名称不用于判断计算阶段。

生成器也区分 `AttackPowerRate`（`panel`）字段，但本白名单没有经核实的这类贡献，
所以不伪造 panel/hit 规则。手填面板只跳过 panel 加成，不应把这些 final 规则吞掉。
防御前预览不能冒充已经应用防御后的 final 加成。

例：7001400 为物理伤害 `×1.04`，6001400 为物理伤害 `×1.105`；
7001500 为魔力伤害 `×1.045`。物理倍率不同时乘到魔力、火、雷、圣分量。

### 命中筛选与开关

- `tags` 全满足；`anyTags` 至少满足一个；`conditions` 全部打开。
  缺失或未核对的标签不匹配，不能按整套战技名称给所有命中段加上标签。
- `atkSubCategory:<数字>` 来自该命中的原生攻击/施法分类。
  例如战技倍率只接受111或112；野兽祷告只接受23，且同时要求 `incantation`。
  这些是原生筛选证据，不应仅凭“看上去像法术/蓄力”赋值。
- `weaponAttack` 限定原生不作用于魔法、祷告及第三施法域的武器命中；
  油脂后的物理强化因此不能泄漏到物理属性祷告。
- `sorcery` / `incantation` 来自施法域。`critical` 和 `piercingCounter`
  分别限定原生致命与突刺反击条件，不是所有近战动作。
- `heldWeaponType:<原生WEP_TYPE数字>` 对应 `triggerOnWepType`。
  它与“背包里三把武器”不同；后者只作为独立的装备条件开关，
  不能误将它的伤害增益限制为这类武器打出的命中。
- 原生100/110分类的蓄力增益均要求显式勾选「已蓄力」。
  不勾选没有额外词条增益；已选动作自己的蓄力修正不会再乘一次。
- 满血增益显式要求「满血」。低血量阈值按原生参数记录；
  6851200及8810000系列阈值为84.99%，不能照旧译名简化成“任何不满血”。
- 复仇者7220000只建模弗雷德利克对应的玩家伤害 `×1.1`，
  角色 ID 使用面板模块约定的字符串 `"6"`，并要求实际强化已生效。
  海伦治疗、塞巴斯蒂安减伤及召唤家人自己的伤害没有混入该倍率。

本版原生8320100/1/2为 `×1.16/1.19/1.22`，而旧快照写 `6/9/12%`；
7040201为 `×1.23`，7043000为 `×1.15`，6043100为 `×1.3`。
采用当前原生字段，不套用旧说明的数值，也不回写旧图鉴。

### 叠加与整个增益的覆盖

原生 `spCategory=10` 按 Stack Self 输出 `stackRule: multiply`。
同一主动效果的刷新或相同等级不可叠加，使用该实际 SpEffect 的独立 `stackGroup`
和 `highest`；不同等级若是独立效果，组外乘算。
例如7030900重复触发只计一次 `×1.1`，与6030900并存为 `×1.1×1.17`。
没有用 compatibilityId 生成跨遗物叠加组，也没有把所有 category=10 合并成一组。

`exclusiveGroup` 与组内最高倍率是不同机制：同一覆盖组**后选的整个 buff**
覆盖此前 buff 的全部规则，包括其他属性的贡献。先按生效状态筛选再确定覆盖，
一个未生效的后选 buff 不应删除仍在生效的前一个。

- `spCategory:151`：勇者肉块、火焰啊，赐予我力量、狂热香药的身体增益。
- `spCategory:160`：老将的军旗、黄金树立誓（战技或祷告）、振奋香的攻击增益。同组同优先级，后生效的覆盖之前的。
  振奋香另外的屏障效果是159组，不参与本伤害输出倍率。
- 四种属性露滴和大刺破露滴以自己的物品 ID 分组，重复使用只刷新该物品增益；
  不把所有 `spCategory=201` 项简单合成一个全局组。

## 未表达的规则

`unsupported` 记录明确缺口：监牢/入侵者击杀次数的累乘、独立计时的连击/击杀层数、
异常条成长阶段、按人物血量加固定伤害、按目标最大血量加伤、随机附魔、
出击武器按种类进行的固定攻击力转换、女爵重演的复制比例等。
双手共持（8300000–2）与双持（8310000–2）分别检查命中段的原生分类124、125；三个档位分别为 +12%、+15%、+18%。双手短剑轻击 100200 有124，六个展示战技的已解析攻击段均无124。不能仅根据持握姿势给整个战技加伤。
对上述两个词条系列及军旗、战技黄金树立誓、水母盾，按原生标记读取每段的 `spEffectAtkPowerCorrectRate_byDmg`：100 时全额，0 时不计，其他按比例作用于增量。无该字段的命中不推定得到全额。紫色强化一级即达到金色，火山不另算一次强化；红武仍使用独立修正。
力量、灵巧、智力、信仰、感应的固定点数必须交给面板补正重算，不折算成百分比；
选择含这些未建模词条的固定遗物，不表示整件遗物的面板变化已计算。
强化调和品的 level2/level3 引用与基础 refId 不可互换，本轮只收录基础物品版本。
复仇者7031200的触发和接受者链尚未完整核对，未猜测为无条件玩家加伤。

新增规则前必须补上原生来源、适用分量、触发条件和叠加依据；
无法核对的效果不自动填 `rate=1`，也不据遗漏宣称选择的整件遗物已完整计算。

## 独立战技弹体与数量校核

一次耗蓝释放按一发弹体计算。光环镰刀的攻击行 301902901、301902911、301902921 各属一次输入，贴身刀刃单列。使命短刀 300116900 属于黄金刀刃。辉石克力士 300107901 和 300107900 分别是未蓄与蓄力。火焰长牙 300200821 是炎击的起手火焰，采用攻击行覆盖的补正表 51040，仅按力量系数 25 和火属性曲线 4 计算；未解析的额外引用 2003 单独保留。

计算读取各行的属性基础值、武器强化档的 baseAtkRate、有效能力值及属性补正。原生参数换算到玩家菜单数值采用 0.6，源于对十位渡夜者、12 级和 15 级的武器菜单比较；本作 GameSystemCommonParam 行 0 的 +0x30C 与 +0x310 均为 0.6，攻击结果处理分支读取这两个值。手填最终面板只提供刀身等面板命中所需的数值，独立弹体继续读取当前角色属性。[武器面板实测表](https://docs.google.com/spreadsheets/d/1J_4rxMAFlTG1b0xtFSQQXg8A_Y2CdYZAnnAF0v0Hmu4/edit)

15 级、无遗物条件下，将普通品质光环、黄金刀刃、未蓄和蓄力彗砾的结果分别向下取整，与十位角色的训练场记录逐项相符。原作者没有单列火山金色、红色或不同深夜等级的单发读数。火山升金读取金色强化行。红武的独立修正见下文。炎击火焰目前依据本作参数推算。[训练场逐角色测试](https://funa0107.hatenablog.com/entry/2026/01/16/182645)

图鉴目标目前记录的各属性基础防御都是 100，与训练木桩相同。默认扣血以同基础防御的单发参考值乘目标对应受伤倍率，额外计入已生效的伤害词条。手填实战防御时使用现有参考曲线；特定场次的隐藏修正未计入。

## 深夜红武的武器与弹体修正

版本 1.3.3.0（Steam Build 22818764，regulation 10350000）。已收录的战技配对中，光环镰刀、尸山血海、辉石克力士和使命短刀分别命中三条可掉落红武配置。它们都引用原紫武的基础武器 ID，掉落强化档为 0。两种品质使用相同的角色属性、能力补正与战技攻击行。

本版本从 EquipParamCustomWeapon 的 isCursed 字段读出红武标记，写入装备记录，再复制到攻击上下文（RVA 0xE74AAD、0x6A2359、0x6D1A26）。同一装备标记在本作攻击计算中选用两个单精度系数。武器五属性面板读取 GameSystemCommonParam 第 0 行 +0x47C（1.10），独立攻击行的基础属性分量读取 +0x480（1.07）。两条路径分别见本版本武器计算 RVA 0x6C3499 和独立攻击计算 RVA 0x6C4977。旧版 Paramdex 导出的字段别名是 rewardMultiplierSuperTargetBoss3/4，生成器按上述参数版本、路径与实值核对。光环的基础圣攻击为 170，计算时保留 170 × 1.07 的小数，再套原强化行和角色补正。刀身读取已修正的武器面板。

计算器沿用现有目标防御估算和逐段规则。面板系数另有游戏对照，可见[同一把弓的紫红面板](https://img.gamewith.jp/img/76fc72efc91663a1fd2e0db82e32c2da.png)和[同场三把石像鬼黑斧](https://www.reddit.com/r/Nightreign/comments/1st1cdf/ar_difference_between_purple_gold_red/)。红色独立弹体的依据来自本版本游戏计算路径。装备随机获得的属性攻击等词条在选中后另行计算。
