## 已批准的交互与判断规则

- 一个“地图与夜王推算”入口，共用地图配置与线索状态；可以从已知夜王进入，也可以从地图标注进入。
- 地图为主界面，顶部仅保留地形、可不选的夜王和重置。地形初始为“全部地形”，只有用户明确选择才筛选；底图跟随当前候选并显示地形名。点位弹出建筑／主遭遇首领图标名称选项，点击后即时筛选，已选位置以可删除标签显示；同点选择其他同类对象会替换原线索。
- 第一／第二夜首领、已见事件与按名称标点收在“更多线索”，删除队伍 DLC 控件及页面筛选条件，未核验的深夜等级不提供禁用控件。可撤销或删除条件，重置清除所有线索并恢复“全部地形”。
- 增加地图可视高度，默认按可用地图区域放大，保持比例；提供全图适配和放大后拖动。点击标记直接选择该位置对象，不再从所有配置重新搜索附近编号；真正重叠的标记在地图上展开，以图标和名称区分。保留按名称选择的键盘/手机入口。
- 建筑、据点首领、野外精英怪为三个可独立显隐的图层。用户明确新增的是野外精英怪，不能把据点首领或普通怪物统一计作精英怪；身份和位置由怪物数据专项提供，前端依据明确分类显示。
- 未标记不代表不存在。未核验字段不参与硬性排除候选；不得将缺数据当作已确认没有。
- 结果精简为剩余地图数、可能夜王和上一张／下一张候选切换；地图显示当前候选的已核验点位，区分已标记与推算点位，不默认展示配置编号或重复点位长列表，不把不同候选拼成一张确定分布图。
- 零候选保留用户线索，并提示检查冲突或资料覆盖范围；不将配置比例或菜单抽选权重当成真实概率。
- 普通/强化、阶段、召唤物和突袭事件保留身份语义，不能只按同名合并。夜王身份与具体形态分别核验，未确定形态保留未知。
- 底图、坐标、地图方案、首领与事件引用须先闭合再接入筛选。原始文件和完整证据保存在仓库外；网页仅装载所需的派生资料。

## 数据接口约束

数据专项先提交最小接口样例，总控确认后前端实现；公共接口保持 `schemaVersion: 1`。

2026-11-10 实施接口已据真实 `patternId=0` 样例定稿，样例在证据目录 `data/schema-sample.json`。顶层为 `sourceVersion`、`definitions`（按 ID 索引的 `nightlords`、`bosses`、`terrains`、`features`）及 `patterns` 数组。ID 比较统一转为字符串，允许源字段保留安全整数。

- `patternId` 为方案键；`terrain` 使用 `{state,value}`；`nightlord` 使用 `{state,menuRowId,bossNameId,form,formCertainty}`，其中 `menuRowId` 指身份参考菜单行，不代表已确定实战形态；前两夜为 `dayBosses.day1/day2` 的 `{state,sourceId,identityStatus}`。
- `eligibility.depths` 为 `{state,values?: number[]}`；`eligibility.allPlayersHaveDlc` 为 `{state,required?: boolean}`。未知不影响候选。深夜模式运行关联的证据与局限单独记录，不能由菜单权重补造配置可用性。
- 每个 `points` 项使用 `{attachId,world,normalized,features,coverage}`；`features` 是 `{kind,state,sourceId?}` 数组，`kind` 为 building、monster 或 event。允许同一点存在多类和多个实体。`normalized` 为 null 或 `{x,y}`，取值 0–1、左上原点，绑定当前方案地形底图；未校准保持 null。
- 每点 `coverage[kind]` 的 known 表示该类已完整列举，可排除其他取值；known_absent 表示已确认没有该类内容；unknown 表示不能据未列出内容排除。已知 feature 在 coverage 未完整时仍可支持正向匹配，但不可支持否定结论。缺少整个点位默认未知，只有明确完整点位覆盖后才可视为不存在。类型分类尚不清楚的原始 ID 不作为面向用户的已核验选项。
- 公共底图清单按 `terrains[terrainId]` 给出 `{src,width,height,status,source,...}`，status=verified 才使用图片；src 仅允许安全的 `/map-assets/` 本地图片路径。坐标转换完整记录在清单与资产文档，前端只用已校准归一化坐标。
- 已核验的全局事件可通过兼容扩展 `definitions.events` 和 `pattern.events={state,values:[{sourceId,day}]}` 提供。事件身份与发生日分开筛选；明确相同事件族的不同原生标志可共用选择项，不能仅按同名合并。日次未知不用于排除，位置未知时仅作为文字线索和结果，不生成地图落点。事件定义保留原生标志、中文文本与交叉核对依据。
- 已核验的点位主首领使用 `role: primarySmallBaseBoss`。用户明确选择“该点主遭遇首领”后，线索带同一角色；只有候选点的 `coverage.primarySmallBaseBoss=known` 才比较该角色首领并排除不符项。首版仅对 17 个已核验模板赋此覆盖状态，其余模板未知；`coverage.monster` 继续未知，不能据主首领排除普通怪、召唤物或突袭怪物。
- 野外精英怪新增 `role: fieldElite`、`displayCategory: fieldElite`，采用原生模板 ID 作为 `fieldElite:<mapId>` 来源键；对应 `coverage.fieldElite` 独立判断。原有据点主首领使用 `displayCategory: baseBoss`，角色保持不变。类别同时随 feature 和 definition 提供，不能通过同名归并混用两种角色的覆盖状态。已补入 11 个精英模板的 2,850 条方案点位；红狼使用明确标注来源的展示译名，不伪造官方文本 ID。

- 地图方案以明确的 `patternId` 标识，带版本、适用地形、夜王身份、前两夜首领、条件/修饰项及核验状态。
- 点位使用稳定来源 ID，保留原始世界坐标；面向页面另给绑定底图/地形的归一化坐标及建筑、怪物、事件 ID。名称、分类与图片通过独立定义关联。
- 每类字段区分“已核验值”“已核验不存在”“未知/未覆盖”。候选交集与共同点位计算必须尊重这三个状态。
- 底图使用独立清单，包含本地资源路径、尺寸、适用地形、坐标变换、源哈希与核验状态。公开数据使用本地安全路径；清单/图片失败应保留文字筛选能力。
- 地图配置、展示夜王与实体/遭遇 ID 分层；只有已验证关联可用于筛选。来源、版本与覆盖范围在文档完整记录。
- 用样例证明实际可用筛选链，不以静态名录或演示数据冒充已完成的推算功能。

## 验收门槛

1. 底图来源、原尺寸/裁切像素和坐标变换有证据；至少三个已知地点核对方向与定位。
2. 首领/夜王名称、地形、模式/深度与 DLC 条件可追溯，无法核验的条件不伪造确定性。
3. 正向夜王筛图与反向位置线索使用同一配置集；验证唯一、多候选、未知、冲突与撤销恢复，添加可靠线索不得凭空增加候选。
4. “共同”与“可能”图层依据真实候选计算，未知不会误显示为共同或确定不存在。
5. 手机和桌面点选、名称选择、缩放、图层开关、键盘操作与侧栏可达；数据/底图失败有可理解回退。
6. 武器两段文字准确删除，两列临界宽度、长名称、分页/选中操作与固定战技说明通过核验；原图鉴、助手和反馈入口回归。
7. 构建写入仓库外，tracked dist 不变；保留源码/数据/构建哈希、截图和局限说明。无真实模型调用或测试反馈提交。
