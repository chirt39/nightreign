# 产品需求：渡夜图鉴

状态：首轮整理，等待用户逐项确认。来源为现有网站源码与本项目历次用户要求；“现有实现”只表示源码中能找到相应界面或逻辑，未表示数值或体验已经验收。

## 1. 目标与边界

面向《艾尔登法环 黑夜君临》PC 玩家，提供可信的敌人资料、浏览器本地存档解析、遗物收藏筛选、战斗记录与基于实际收藏的配装推荐。网站为非官方玩家工具。界面先适配 PC；移动端不作为当前验收目标。数据完整度和依据必须可见。

### 核心使用路径

1. 玩家在图鉴中按分类或名称找到敌人，查看魔、火、雷、圣倍率及异常抗性。
2. 玩家在遗物仪式中选择本机 `.sl2`，网站在浏览器内解析，展示全部遗物与原有词条顺序。
3. 玩家在日志中查看可确认的战绩字段；无法确认的字段明确标示，不填充猜测值。
4. 玩家在遗物装配中选渡夜者、器皿与流派规则，只从可放入槽位的已拥有遗物中选择，并查看推荐原因。
5. 玩家如需修改存档，先取得原文件备份，再通过独立的编辑与导出流程操作；此能力需要单独验收。

## 3. 非功能需求

- 以 1280px 及以上 PC 窗口作为设计与验收基准；长词条完整可读，分页控制可见且容易操作。
- 解析数千件遗物时，筛选、分页和槽位操作应保持可用；具体性能阈值在真实样本测量后确定。
- 网站不主动请求用户的 Steam 凭据，不收集原始存档；本地缓存范围、清除方法和导出行为写入界面说明。
- 无数据时显示明确空状态。解析失败、缺字段、数据版本不匹配和推荐无解分别说明原因。
- 游戏原始数据、社区整理、人工推断必须可区分；内部 ID 可以辅助核对，但默认文案面向玩家。
- 导航、选择框、搜索、弹窗与拖拽均应保留键盘可用路径。

### AI 咨询与反馈可靠性（已部署；正式 AI/UI 验收待总控）

- AI 接口按 IP 滚动 60 秒最多 20 次；每日实际模型请求仍最多 100 次。超限响应包含服务端计算的 `Retry-After`，CORS 向前端开放该响应头。客户端应保留输入并按倒计时恢复提交。
- 使用 `session_id` 的聊天请求不重复上传历史；无会话时仅在请求副本中按完整轮次控制历史长度。单条历史消息上限 1200 个字符，超限时返回可读提示，不改动展示或持久化的原对话。
- 用户可选择是否附带反馈上下文。选择后最多附带 10 轮；每轮问题最多 400 个 Unicode 字符、每轮回答最多 20,000 个 Unicode 字符，所有轮次合计最多 20,000 个字符。超限明确提示，不截断。取消选择时不得存储上下文。
- 反馈 SQLite 迁移采用新增可空 JSON 列，保留旧标量问答和 90 天保留规则；管理员接口把旧单轮数据与新多轮数据统一为 `context_turns`。
- AI 回答保留原始 `answer` 字符串，并声明 `answer_format: "markdown"`。只允许标题、表格、列表、加粗和站内锚点链接，不允许 HTML、图片和外链。敌人资料明确列出弱点、伤害倍率和抗性；遗物表格分列词条、效果与触发条件，来源未说明时不得推断为“无条件”。
- 仅在本轮检索恰有一个敌人 ID、模型返回精确匹配 ID 且 ID 在已验证本地图像清单中时返回 `verified_enemy_id`；否则不提供图片 ID。
- 敌人资料不得恢复五个已退役承受率字段。正常助手历史仍用于追问连续性；仅命中退役字段的旧回答片段过滤出模型上下文。
- 代码默认和生产环境每分钟限额均为 20；生产每日模型请求上限为 100。已通过服务健康、知识状态、持久化列与静态资源哈希核验。正式站 AI 表格回答与浏览器 UI 复核由总控另行完成，未完成前不记为通过。
