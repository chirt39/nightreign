# 产品需求：渡夜图鉴

## 开工必读

《渡夜图鉴》供《艾尔登法环 黑夜君临》玩家查资料、推算深夜地图和分析自己的遗物收藏。各对话开工时先读本节，再按任务查下方需求编号。这里记录用户已确认的要求，文末按日期保留早期方案；同一事项按最新定稿执行。

### 各页面要解决什么问题

| 页面 | 玩家需要完成的事 | 制作时遵循的要求 |
| --- | --- | --- |
| 圆桌厅堂与助手 | 进入常用功能，提问并核对游戏资料 | 数据查询优先用表格、列表或图鉴链接。用户可用“回答有错？向窝反馈”手动勾选相关的多轮问答。普通建议使用独立入口。 |
| 怪物图鉴 | 按名字、ID、分类或遭遇查找怪物，比较弱点与异常抗性 | 名称下面显示出现地点。同一怪物可靠配对的普通与灾域记录归入一条详情，夜王与永夜王分别展示。保留来源 ID 和地点差异。暂时隐藏生命值，已删除的承受率字段也从 AI 语料移除。怪物图放在详情标题旁。 |
| 武器图鉴 | 搜索或筛选武器，查看武器变体 | 显示图片、基础攻击、字母等级补正和有依据的战技候选。战技和攻击属性配对应图标。列表有足够空间时排两列。 |
| 地图与夜王推算 | 选已知夜王找地图，或标记已见建筑、野外精英反推其他位置及第三夜夜王 | 桌面左侧放条件，右侧放地图。手动标注用绿框，可在图标上取消。剩余配置在该点一致时用红框。选项随线索收窄，冲突提示放地图工具栏。建筑用游戏图标，普通、强力野外精英分别用蓝、红图标并显示名字。 |
| 词条图鉴 | 并排比较多个词条的效果与叠加规则 | 使用全宽卡片。叠加条件紧跟词条类型，例如「局外词条」「专属遗物」「不可叠加」。卡片省略「不附带负面词条」标签，保留原始数据和遗物实际携带的负面效果。桌面同排标题、标签、正文起点及底边对齐。每页按实际列数排整行，四列每页 20 条，三列每页 18 条。最后一页按实际剩余条数展示。手机单列，长说明自然换行。 |
| 遗物仪式 | 打开存档，一眼比较多件遗物及其效果 | 全宽卡片直接显示图标、中文名、颜色和全部词条。桌面同排的图标、名称、第一条效果起点及卡片底边对齐，高度随该排内容调整。手机单列按每件遗物的内容自然增高。长词条完整换行，负面词条紧随所属效果。已载入时收紧换存档入口和统计栏，手机首屏能看到遗物。网站移除“导出小程序本地数据”入口，来源信息在仓库留档。 |
| 日志与遗物装配 | 查看存档中的战绩，按角色、器皿和流派选配已拥有的遗物 | 日志按已核实字段展示。逐局记录另行核对，累计数不能拆成单局结果。组合遵循普通／深夜槽位及颜色限制，说明推荐理由，玩家确认后才应用到预览。 |
| 资料说明 | 查阅资料依据和许可 | 内容由用户定稿后再重做。 |

### 视觉、数据与隐私

- 打开、搜索或关闭选择器时，周围控件的位置、宽度和整页滚动位置应保持稳定。选中或取消后，焦点回到原选择框。选中词条后需要填写的负面栏按规则展开。
- 检测收藏时，在原卡对应的正面或负面词条旁标「异常」。有确认异常时提供单独的异常遗物视图；未发现异常只在检测按钮旁提示。资料待核对不算异常，第四个原始保存槽不作为玩家可选槽位。手动检测确认冲突只显示「异常」。
- 候选多时只滚动候选列表。即使选择框靠近手机屏幕底部，玩家也应能在当前位置看到搜索框、浏览到最后一项并选中，无需向下滚动整页。桌面按上下可用空间展开浮层，手机按当前可视区域调整高度。

- 调整布局只改用户指定的内容。若要新增玩家可见的标签或说明，先向用户确认具体文案和位置。
- 沿用图鉴的深蓝底色、金色强调、标题与控件间距。按照页面用途决定布局。搜索框的焦点边框贴合整个控件，键盘操作时能辨认当前位置。备案链接保持可达。
- 游戏数据和图标登记来源、版本及关联 ID。怪物详情优先使用核准图片，候选图保留匹配依据和纠错入口。暂缺的数据保留缺失状态。详见[怪物图片](ENEMY_IMAGES.md)、[武器数据](WEAPON_DATA.md)和[地图数据](MAP_DATA.md)。
- 本机选择的存档在浏览器内解析。Steam 云文件经后端临时转发时，界面如实说明来源。仓库和验收附件使用合成或经授权脱敏的样本。存档写回需单独验收。
- 意见箱由管理员私密查看，保留 90 天。反馈不收集联系邮箱，问答附件默认不选，用户选择的内容才随反馈发送。

### 从接需求到交付

1. 总控是用户入口。先用中文澄清影响结果的问题，给出涉及页面或文件、验收方式和发布影响。用户批准后，由总控将任务交给对应专项对话。跨模块任务写清主责和接口。
2. 专项对话提交改动和验收证据，总控对照用户给出的场景复核。布局改动至少看桌面和手机两种宽度，对照卡片密度时使用相同窗口和示例数据。多列分页同时检查首行、页尾和翻页，核对筛选或改变列数后所有匹配记录都能浏览且各出现一次。对话之间通过仓库文档、Issue 和 PR 同步。职责见[对话分工](WORKSTREAMS.md)。
3. 交付时提供可打开的预览和验证结果，明确本地预览、GitHub 合并和正式上线的状态。按用户授权发布到 nightreign.cn，记录正式提交、回滚版本及公网验收结果。[发布记录](RELEASES.md)及[武器、地图和怪物图鉴正式发布 PR](https://github.com/chirt39/nightreign/pull/40)可供核对。

## 1. 目标与边界

网站为玩家制作的非官方工具。桌面优先展示便于比较的数据，手机采用适合窄屏的布局。资料依据和已知缺失可追溯。

### 核心使用路径

1. 玩家在图鉴中按分类或名称找到敌人，查看魔、火、雷、圣倍率及异常抗性。
2. 玩家在遗物仪式中选择本机 `.sl2`，网站在浏览器内解析，展示全部遗物与原有词条顺序。
3. 玩家在日志中查看可确认的战绩字段；无法确认的字段明确标示，不填充猜测值。
4. 玩家在遗物装配中选渡夜者、器皿与流派规则，只从可放入槽位的已拥有遗物中选择，并查看推荐原因。
5. 玩家如需修改存档，先取得原文件备份，再通过独立的编辑与导出流程操作；此能力需要单独验收。

## 3. 非功能需求

- 以 1280px 及以上 PC 窗口作为设计与验收基准；长词条完整可读，分页控制可见且容易操作。
- 解析数千件遗物时，筛选、分页和槽位操作应保持可用；具体性能阈值在真实样本测量后确定。
- 网站不主动请求用户的 Steam 凭据，不收集原始存档；本地缓存范围、清除方法和导出行为写入界面说明。
- 无数据时显示明确空状态。解析失败、缺字段、数据版本不匹配和推荐无解分别说明原因。
- 游戏原始数据、社区整理、人工推断必须可区分；内部 ID 可以辅助核对，但默认文案面向玩家。
- 导航、选择框、搜索、弹窗与拖拽均应保留键盘可用路径。

### AI 咨询与反馈可靠性（已部署）

- AI 接口按 IP 滚动 60 秒最多 20 次；每日实际模型请求仍最多 100 次。超限响应包含服务端计算的 `Retry-After`，CORS 向前端开放该响应头。客户端应保留输入并按倒计时恢复提交。
- 使用 `session_id` 的聊天请求不重复上传历史；无会话时仅在请求副本中按完整轮次控制历史长度。单条历史消息上限 1200 个字符，超限时返回可读提示，不改动展示或持久化的原对话。
- 用户可选择是否附带反馈上下文。选择后最多附带 10 轮；每轮问题最多 400 个 Unicode 字符、每轮回答最多 20,000 个 Unicode 字符，所有轮次合计最多 20,000 个字符。超限明确提示，不截断。取消选择时不得存储上下文。
- 反馈不收集联系邮箱；历史邮箱值按既有 90 天期限保留，不由管理员接口返回。
- 反馈 SQLite 迁移采用新增可空 JSON 列，保留旧标量问答和 90 天保留规则；管理员接口把旧单轮数据与新多轮数据统一为 `context_turns`。
- AI 回答保留原始 `answer` 字符串，并声明 `answer_format: "markdown"`。只允许标题、表格、列表、加粗和站内锚点链接，不允许 HTML、图片和外链。敌人资料明确列出弱点、伤害倍率和抗性；遗物表格分列词条、效果与触发条件，来源未说明时不得推断为“无条件”。
- 仅在本轮检索恰有一个敌人 ID、模型返回精确匹配 ID 且 ID 在已验证本地图像清单中时返回 `verified_enemy_id`；否则不提供图片 ID。
- 敌人资料不得恢复五个已退役承受率字段。正常助手历史仍用于追问连续性；仅命中退役字段的旧回答片段过滤出模型上下文。
- 代码默认和生产环境每分钟限额均为 20；生产每日模型请求上限为 100。服务、知识状态、持久化列和静态资源哈希已核验。正式站一次 AI 表格回答与浏览器布局/反馈弹窗已由总控验收；验收发现普通敌人问题会主动提及已退役字段，且有两处显示名需按图鉴收窄。相关提示词修正已由 PR #33 合并并部署；修正后的提示词通过 mock prompt 测试，本次部署后未再次发起真实 AI 问答。
