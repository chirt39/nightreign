# 六武器附带词条与属性点

生成器：`scripts/build_damage_weapon_traits.py`。
数据：`public/damage-weapon-traits.json`。
测试：`tests/damage-weapon-traits.test.mjs`。

## 来源和范围

本机提取 `nightreign-data-20261109`，游戏 `1.3.3.0` / regulation `10350000`。
生成器展开 XML 默认值，保留重复 ID 的加权候选行，不把表的最后一行当整池。
所有输入的 SHA-256 写入 `metadata.sources`，计算规则快照另有哈希。

| 武器基础 ID | 预览变体 ID | 核对战技 ID | 有引用且支持该战技的配置数 |
| --- | --- | --- | --- |
| 19020000 光环镰刀 | 19020000 | 1051 米凯拉的光环 | 6 |
| 9040000 尸山血海 | 9040000 | 1177 尸横遍野 | 6 |
| 9080000 蛇骨刀 | 9080000 | 112 二连斩 | 4 |
| 9010000 长牙 | 9010500 火焰长牙 | 214 炎击 | 3 |
| 1070000 辉石克力士 | 1070000 | 1017 辉石彗砾 | 6 |
| 1160000 使命短刀 | 1160000 | 1037 黄金刀刃 | 6 |

词条源是 **EquipParamCustomWeapon** 的 `targetWeaponId` 与六个 `attachEffectTableId_*`，
不是 EquipParamWeapon 默认的 `attachEffectId=-1`。
先核对 ItemTableParam/ItemLotParam 中正权重的 CustomWeapon 引用，
再核对 SwordArtsTableParam 中是否有对应战技，排除没有这些依据的测试配置和不符战技。
这证明静态引用关系，不证明每个事件条件下都能获得某一配置。
`disableParam_NT` 只说明网络测试包条件，不单独作为正式版不存在的证据。

31条配置保留在 `profiles`，每条有完整六字段池向量及掉落引用例子。
`sourceRefs` 为每个“武器/池/模式/诅咒状态”保留一条原生链示例，
完整配置由 `profiles` 查验，避免大量重复输出。

## 选项和状态

共250个选项：正面174、负面46、不甘30。
50个已有可复用倍率，42个缺伤害规则，131个不直接改变本次命中伤害，27个需要属性补正重算。
一个选项的 `effectIds` 可有多个，必须全部引用，不能仅取第一条。

| calculationStatus | 含义及上游处理 |
| --- | --- |
| `supported` | 使用 effectIds 引用的原生伤害规则，继续匹配属性、动作、条件 |
| `partial` | 仅部分分量有规则，保留缺口；本版暂无这类条目 |
| `stat-gains` | 将 statGains 加到面板补正前的实际属性点，不能当成无效果 |
| `non-damage` | 不直接改变本次命中输出；恢复、减伤、状态抗性、资源等效果仍存在 |
| `missing-rule` | 尚缺触发、额外命中或换算，必须提示未完整计算，不能显示为确定0贡献 |

`polarity` 只查原生 AttachEffectParam.isDebuff，**不按名称猜**。
例如8520001“敌人比较不会攻击自己”在原生表中为负面，
501/505等普通正面为主的池也有负面候选。
字段4的610/620池是负面池，字段5/6仍按各候选自己的标志分类。

`modes` 的字段约定是1–3为普通来源组、4–6为深夜来源组；
根据本轮用户明确的“红武只在深夜”要求，`isCursed=1` 配置的所有字段均归深夜来源。
不能把“isCursed=0”倒推成普通模式，也不能把每个候选都理解成必带。
本数据不校验任意多个词条能否共存；不能用各自有来源替代整件遗物/武器组合的合法性。

## 新补的倍率和严格限制

`build_damage_effects.py` 新增15条原生局内规则，累计209条计算规则。
新增包含近战、冲刺、翻滚、物理、属性、施法、突刺反击，以及负面8810050。

- 8810050为五属性伤害 `×0.93`，原生 HP 触发阈值84.99%。
  复用「低血量攻击效果已触发（原生阈值84.99%）」开关，不无条件减伤害。
  它与「满血」不可能同时满足；页面应保持真实状态，不同时启用矛盾条件。
- 8850500/8850550为物理 `×1.08/×1.10`，不同时乘属性伤害。
  8850600/8850650只作用于魔力、火、雷、圣，物理不变。
- 8851200/8851250的原生 wepParamChange=3 且只启用施法域，
  使用 `anyTags=[sorcery,incantation]`；不能套到刀身或战技上。
- 83205/06/07系列保留原生130、127、128/129逐段分类，
  不能给整套动作统一加成。蓄力相关词条继续使用「已蓄力」开关。
- 8821000/8821050虽有 `AttackRate=0.01`，但还带随机掠过的状态2121；
  未确认概率与这一次攻击是否触发，不输出全程0.01倍率，也不自行算期望值。
- 双手/双持的 `isUseAtkParamAtkPowerCorrect`、861系列追加属性命中、
  自动辉剑和蓄力生成熔岩等是不同的换算/附加命中问题，保留 `missing-rule`。
- 精力伤害或削韧的倍率不等于生命伤害倍率；不能因字段含 AttackRate 就用于扣血。

## 红武随机词条

六组预览中，光环镰刀、尸山血海、辉石克力士、使命短刀各有三条可追溯的红武配置，共 12 条。蛇骨刀配二连斩、火焰长牙配炎击没有找到对应的红武掉落配置。

以光环镰刀的 `19025000` 为例，三个词条池依次为 `630000000`、`501200200`、`810000000`。前后三个原生字段引用相同的三池。每个候选从其槽位的池中抽取。另两条配置替换中间槽的池。同一槽中出现的两个词条不能一起装备。

| 词条池 | 可核对的攻击效果 |
| --- | --- |
| `630000000`（22 项） | 负面 `8810050` 的五属性伤害系数为 0.93，需满足原生生命阈值。随机掠过 `8821050` 带状态 2121，不能当作常驻倍率。 |
| 由具体配置指定 | 随机武器词条或单项池。按所选武器的实际配置、词条 ID、动作和属性取用。 |
| `810000000`（26 项） | `8850550` 物理 ×1.10；`8850650` 魔力、火、雷、圣 ×1.08；`8851250` 魔法与祷告 ×1.08；`8851850` 突刺反击 ×1.15。八个蓄力触发的独立效果另需追踪。 |

以上倍率来自各自的 `AttachEffectParam → SpEffectParam`，随选择生效一次。`ordinaryPeerId` 通过参数内容匹配同武器的普通配置，核验基础武器、强化级别、战技表和其余非词条字段。`redTraitSlots` 保留红武三个实际槽位的池引用。品质的武器面板与独立弹体系数见[深夜红武的武器与弹体修正](DAMAGE_EFFECTS.md#深夜红武的武器与弹体修正)。

## 尸体“xx的不甘”

原生 AttachEffectParam 有1000个不甘 ID，对应10位来源角色，每位有3种计算载荷。
同一载荷的多个内部 ID 以 `aliasIds` 保留，选择器只展示30项。
这是计算等价归并，不是存档 ID 别名重写，也不能用 ID 尾数推算加点。

例如执行者：

| 选择 ID | 实际被动 SpEffect | 属性点 |
| --- | --- | --- |
| 9990800（含9990801等） | 8990800 | 灵巧+3、感应+3 |
| 9990810 | 8990801 | 灵巧+6、感应+6 |
| 9990820（含9990899等） | 8990802 | 灵巧+9、感应+9 |

属性点读取 `addStrengthStatus/addDexterityStatus/addMagicStatus/addFaithStatus/addLuckStatus`。
`statGains` 只包含伤害面板的五属性；生命力、集中力、耐力等另存 `nonAttackStatGains`。
守护者不甘只增加生命力/耐力，不伪造直接攻击倍率。

`sourceCharacterId` 是**来源**角色，不限制接收者；其原生 allow* 标志全开。
例如追踪者也可以在此预览中选择“执行者的不甘”，不能按名字限制成仅执行者。

这些不甘没有普通随机词条池引用；具体尸体赋予哪件武器、何时触发、多份是否叠加，
目前没有完整执行证据。`assignmentStatus` 明确标为未核对，
展示为用户选择的尸体额外槽，不据此保证任意武器的尸体掉落合法性。

## 击败敌人后的属性

`victoryAttributeGains` 约定只输入用户实际已经获得的力气、灵巧、智力、信仰、感应点数。
19700030–19700070是本作显示文本 ID，不是 AttachEffectParam 或可执行加点指令。
未核实“某个敌人/一次击杀固定给几点”的完整来源链，所以 `pointsPerKill=null`、
`automaticEnemyMapping=unverified`；不从击杀数或卢恩推算点数，也不把成长词条的百分比当属性点。

自动面板：将这部分实际点数与已选不甘的 `statGains` 相加，在属性补正曲线前处理。
手填最终游戏面板：跳过这两部分重复加点。
例如不甘+3灵巧/+3感应、实际胜利+2灵巧，则一次传入 `{dexterity:5,arcane:3}`；
不要把它转成“攻击力+5%”或在多个伤害分量上重复加点。

python scripts/build_damage_effects.py
